## Strengths

- The extraction run is always saved before rethrowing, ensuring failed runs are consistently visible in the database rather than lost.
- Using `Neo4jClient` for the cleanup query (instead of a repository method) gives full Cypher control and allows the `RETURN` clause to surface structured diagnostic counters.
- Separation of `runsToDelete` computation from deletion logic is clean and testable.

## Recommended Action

1. **Fix critical first**: Add a `log.warn` when `cleanup.fetch().one()` returns empty so absent results are distinguishable from zero-count results (`GraphExtractionService.java:216-218`).
2. **Separate cleanup from extraction try/catch**: Move `cleanupRunsAfterCompletion` to its own `try/catch` after the run is saved as `COMPLETED`, so cleanup failures don't retroactively mark successful extractions as failed (`GraphExtractionService.java:120-134`).
3. **Add label guards to cleanup Cypher**: Exclude known infrastructure node labels from the unlabeled `OPTIONAL MATCH` to prevent accidental deletion of non-domain nodes (`GraphExtractionService.java:202-206`).
4. **Guard null error messages**: Default to `ex.getClass().getSimpleName() + " (no message)"` before persisting `errorMessage` (`GraphExtractionService.java:135-149`).
5. Re-run this review after fixes to confirm issues are resolved.
